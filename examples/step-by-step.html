The ladder — step by step ​

Every rung below is one file GoMeta can read, shown whole with its line numbers, followed by what the GoMeta Engine evaluated for it — the development tools' own printouts, captured from the package, never typed — and, where visibility is the point, the rendered copy the basic renderer writes. Read it after Getting started's first metaLine, or start here: rung 1 assumes Julia and nothing of GoMeta. Every rung is a Julia file, but GoMeta can be embedded in all kinds of formats (e.g. C, Rust, LaTeX, etc.) — there the GoMeta marker is //~ (the C family) or %~ (LaTeX); see Embedding in all kinds of formats. The first four rungs grow ONE file: the lines a rung adds carry a bold number, a tint and a bar at the left edge; a line a rung only touched carries a dotted number, a lighter tint and a yellow bar; the unchanged lines fold away behind a line that opens on a click, and a long box scrolls inside itself until its bar shows the whole file. From rung 5 on each rung is a file of its own. The comments inside each file carry its point; the paragraph before it says what the file leaves unsaid.

Rung 1 — what BLS sees ​

Before GoMeta can absorb and evaluate the metadata, BLS reads the file and records what it finds as Components: Blocks, Lines and Segments, each of one of three flavors — Text, Meta or Code — and each flavor can contain comments. In the words of the JuliaCon 2026 proposal, "Any line starting with #~ is considered to be a metaline"; here the statement after the marker is hide, a value of the Alterant Visib — what hide does to a copy of the file is rung 2's, rung 1 shows only where it lands. "By positioning such a block just above a block of code or text [no vertical spacing in between] the former gets attached to the latter" — the proposal again; an empty line after a metaLine starts a new Block. The file's own 'metaComponent' and 'metaStatement' are its early names for a Component of flavor Meta and for a statement; its 'sub-section' is nesting under: #~2 opens a metaLine one level deeper than #~, and a deeper metaLine stays under the shallower one above it however many lines lie between — the empty line detaches content from metadata, it does not take #~2 out from under line 8; the levels are rung 5's. Where no statement reaches a Component, nothing applies, and the value is show. The file's own comments say the rest; it is grown from the first Intro-Tour file of GoMeta's early demos: three comment lines re-cut and a markdown Block added.

The grey handle line is the Component's address — skip it on a first reading. Rung 2 — the three values of Visib, and the first rendered copy ​

Rung 1 grown by ten lines. Visib's values are show, hide and discard, and for any one piece of the file only one of them applies at a time. The rendered copy below the printouts is written by the basic renderer, a development tool and a proxy to check by eye what GoMeta has evaluated — what matters is what GoMeta evaluates, not what its proxy shows. A hidden Line is written behind ##, a hidden empty line stays an empty line, a discarded Line is left out, a shown Line is written as it is. The #~ discard on line 26 and the #~ show on line 30 stand beside the first #~ on line 8, not under it as #~2 does, so they inherit nothing from it — the levels are rung 5's.

Rung 5 — the meta hierarchy: the depths ​

A station, a new short file. "For the purpose of inheritance, a hierarchy of blocks of metadata can be defined by appending additional ~s to the head of a metablock's first metaline or, alternatively, adding there a digit representing the desired depth within the metahierarchy" — the JuliaCon 2026 proposal: #~ is depth 1, #~2 or #~~ depth 2, #~3 or #~~~ depth 3, and #~0 is the file level, the shallowest depth, above depth 1. A Component carries the statements of the metaBlock it is attached to and of every shallower metaBlock that one nests under; where two Visib statements reach it, the closer applicable one wins — labels, by contrast, accumulate. A metaBlock at the same or a shallower depth ends the reach of the open metaBlocks at its depth and below: a second #~ is a sibling of the first and inherits from the file level alone, not from its sibling and not from the depth-3 metaBlock between them. The view prints the value that wins; a statement that reaches a Component and is overruled leaves no row. The second Intro-Tour file, rung 6, opens with a condition at the file level: #~0 hide{ :label🍒 && isText }. Every content Block in this file is attached to a metaBlock.

Rung 6 — a label applied and read; the Heading values beside it ​

A station: the second of the two Intro-Tour files of GoMeta's early demos, its label a pictograph. A label is applied with the colon: :label🍒 applies the name label🍒 — a name GoMeta ships with, so the run reports nothing — to the metaBlock that states it and to the Block attached to it, and the view records it as label_label🍒 => true at each Component it applies to; "applies here" in the file's comments means that row. The second #~ metaBlock is a sibling of the first (rung 5) and carries no label: its Block in the view has a heading row and no label row — the sibling rule again, now by a label's absence; labels accumulate, so a missing row is direct evidence. The file-level condition hide{ :label🍒 && isText } is evaluated for every Component it reaches when the Engine applies the statement, so it reads a label applied on a later line, and both halves must hold: it takes the first markdown Block alone. The same construction opens the Documenter example of the JuliaCon 2026 talk, #~0 hide{ :🍻 } over a later #~2 :🍻 (the talk's label a bare pictograph, from before the shipped vocabulary).

A quoted text first on a metaLine is a value of the Heading Alterant; the view records it as head_1 — the 1 its depth. A heading is applied to the metaBlock that states it and to no other Block, where the label reaches the attached Block as well — how far a value reaches is each Alterant's own. Every content Block in this file is attached.
